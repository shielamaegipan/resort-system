# Render deployment

The root `render.yaml` creates two paid services in Singapore: an Express/React web service with persistent uploads and a private MySQL 8 service with its own persistent disk. Review the current Render estimate before provisioning these services. The application and Socket.IO share the generated HTTPS origin.

## Publish

1. Push the reviewed application and deployment files to the repository branch that Render will use. Do not upload the full backup ZIP: it contains local configuration and runtime files.
2. Sign in to Render and create a Blueprint from that repository and branch. Use the root `render.yaml`.
3. Review the paid compute and disk settings, then create the Blueprint. Secrets and MySQL connection references are generated by Render. A first app start can fail while MySQL initializes; deploy the app again after the database is ready if necessary.
4. Verify the generated app URL after its `/` health check passes. Migrations complete before Express starts accepting traffic.

## Existing records and uploads

The MySQL image initializes the base schema only when its data directory is empty. It does not contain local database records, users, or passwords. Normal app startup applies the existing additive migrations. No demo users are enabled in production.

For this existing installation, migrate its database through authenticated private access before handing over the deployment. Back up both databases first, pause writes during migration, and do not reset or overwrite existing production data. Preserve users and their password hashes so their logins continue to work. Copy existing public uploads into the app volume's `/data/uploads` and payment evidence into `/data/private-uploads`. Neither folder nor any `.env` file is included in the Docker build.

The generated Render origin is allowed automatically. Add custom HTTPS origins to `CLIENT_ORIGIN` if a custom domain is configured. Browser push additionally needs the existing VAPID environment variables. Verify login with a migrated account, a room photo, and live chat before considering deployment complete.

MySQL is self-hosted: use logical MySQL backups and a separate upload backup strategy. The template retains the application's existing migrations and does not convert it to PostgreSQL.
