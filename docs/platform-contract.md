# Platform extension contract

Existing `/api/rooms`, `/api/bookings`, `/api/users` response shapes remain compatible. New operations use bearer authentication, `{error}` failures, 400 validation, 401 authentication, 403 permission, 404 missing record and 409 lifecycle/conflict responses. Monetary values are decimal PHP, validated to two places. Payment operations require a unique client-generated `Idempotency-Key` header. Replaying the same key and payload returns the original record; conflicting reuse returns 409.

New endpoints under `/api/ops`: `GET /dashboard?year=YYYY`, `GET /calendar?start=YYYY-MM-DD&end=YYYY-MM-DD`, `GET /bookings/:id`, `PATCH /bookings/:id` (dates/room/requests), `GET/POST /payments`, `POST /payments/:id/verify`, `/reject`, `/refund`, `GET /payments/:id/receipt`, `GET /payments/:id/evidence`, `GET /roles`, `GET/POST /staff`, `PUT /staff/:id`, `POST /staff/:id/reset-password`, `GET /activity`, `GET /rooms/:id/images`, `POST /rooms/:id/images`, `PATCH/DELETE /rooms/:id/images/:imageId`, `PATCH /rooms/:id/operation`, `GET/POST /maintenance`, `PATCH /maintenance/:id`, `GET /settings`, `PUT /settings`.

Payments are cash or manually verified GCash/Maya/bank-transfer records. No gateway integration or automatic verification is claimed. Verified payments less recorded refunds drive cash revenue; historical booking-value reports remain separate. Receipts are payment acknowledgments, not BIR official receipts. Refunds record externally executed refunds; they do not move money. Check-in requires today's eligible confirmed reservation, ready room and no active occupant. Checkout requires a settled balance and moves the room to cleaning. Room locks serialize creation, reassignment, status transitions and availability checks. Archived historical records are retained.

Permission profiles are stored separately from legacy admin/staff/guest roles. Existing admins retain Admin permissions; Super Admin must be explicitly provisioned through the local bootstrap command. Permissions are queried for each request. Existing staff map to Receptionist. Housekeeping can only inspect room readiness and update cleaning/maintenance workflows. Socket connections recheck active profiles before delivery. New writes append actor/entity history, persist authorized notifications and invalidate server-state caches.

Migrations are additive except widening the room-status enum; no record deletion, automatic administrator promotion or automatic sample seeding. Rollback requires stopping new writes, exporting added tables/columns, and reverting application code; retain financial/audit data. MySQL DDL implicitly commits, so take a database backup before deployment.
